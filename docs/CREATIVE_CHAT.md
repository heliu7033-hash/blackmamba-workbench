# 创意方案中的文案智能体

创意方案的第一个工作区是按项目保存的对话。默认使用本机已登录的 Codex CLI，点击发送才调用模型。Codex 由本机启动，推理仍使用账号对应的在线服务；项目名称、简报和该项目对话会作为上下文发送。对话记录在本机 `data/creative-chat`，不进入 Git，也不包含在原有浏览器项目备份中，可单独点击「导出对话」。原项目简报不会被自动覆盖。

## 问答规则

1. 用户先输入创作需求。
2. 智能体依次围绕目标、创意方向、表达与结构提问。每轮根据上下文构思 3–5 个方向，每项包含名称、方向性问句和简短依据。
3. 选择一个方向并补充细节，或直接输入自定义方向，才推进本轮。「补充后重新提问」保留当前进度，重新提出针对性问题。
4. 完成三轮选择后，界面才开放「生成完整文案」。按钮旁输入了新要求时，先讨论新要求，不会丢掉补充直接生成。
5. 文案完成后可复制、导出对话、保存为「文案第 N 稿」（待复核）。修改文案也先通过一轮方向问答，再生成新版本。

服务器校验阶段、当前问题 ID、版本号、选项数量、问句、重复标签和必填字段；请求携带 UUID，重复提交不重复执行。未通过规则的回答不会加入对话，用户可重试。数量和阶段门禁是确定性约束，方向的语义差异与创意质量仍依赖模型判断，不能用结构校验保证。界面只显示简要依据，不要求公开模型内部推理。

每个项目独立存储、串行提交。后台生成结束后可回来继续；服务重启导致的未完成任务会显示中断和重试入口。每条用户输入最多 6000 字，背景 10000 字，文案 18000 字，每项目最多 240 条消息；最近 60 条对话和全部确认决定进入下一轮上下文。

## 保存与稿次

每个项目独立编号；同一生成结果重复保存不增加稿次。旧版「智能体文案 / 对话生成」记录按保存顺序显示稿次，普通简报和导演补充不会被误算为文案。新增记录显式保存来源与稿号，完整正文保留在项目备份中。

项目树和阶段页面显示最新一稿，历史稿折叠查看。文案正文只读，可复制和继续对话；审核状态单独更新，不改动旧稿正文。保存稿件或标记「已确认」不会自动推进项目阶段或勾选清单。

## MCP 智能体扩展

「添加智能体」支持 Streamable HTTP MCP：填写名称与地址 → 读取工具 → 选择对话工具与字符串输入字段 → 添加。支持 `initialize`、初始化通知、分页 `tools/list`、`tools/call`、JSON/SSE 响应与会话结束。远端要求 HTTPS，本机允许 HTTP；不自动跟随重定向。

MCP 服务需要提供能接收完整提示词的对话工具，例如 `chat({prompt: string})`。其他必填输入可在附加 JSON 参数中填写。工具必须返回提示词要求的 JSON（文本 content 或 structuredContent），普通检索/文件工具不能冒充文案智能体。所有提供者经过相同流程门禁。

认证可填写环境变量名称，令牌只由服务进程读取，不由网页保存。原生应用会转发启动环境中 `MAMBA_MCP_` 前缀的变量，例如 `MAMBA_MCP_TOKEN`；变更后需重新启动应用。当前未实现 stdio、OAuth 登录、旧版 HTTP+SSE 双端点传输或任意工具编排。未接入真实第三方服务时，只能声称协议测试通过。

协议依据：[MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)、[MCP Tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)。

## 验证

- `node scripts/test-creative.mjs`：问答门禁、失败恢复、版本冲突、幂等、隔离、持久化和本机 MCP 模拟服务的真实协议交互。
- `npm test`：工作台全量回归（包括素材库与达芬奇导入测试）。
- UI 使用独立端口及临时数据目录。真实 Codex 验证只使用虚构项目，不使用私人客户资料。
